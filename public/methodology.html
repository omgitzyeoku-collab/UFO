Methodology

This page describes exactly how a document goes from "PDF on war.gov" to "plain-English summary on UAP Files." The pipeline is auditable — every step is open-source code in the project repo.

1. Acquisition

A web crawler pulls the document index (a CSV file) from war.gov, then downloads each PDF, video, and image referenced. Every download is hashed (SHA-256) and stored content-addressably. We never alter the source files.

For verification: download any file from our GitHub Release, run sha256sum, and compare to the SHA-256 in our manifest. They will match byte-for-byte.

2. Text extraction

For born-digital PDFs (modern mission reports, NASA debriefs, State Department cables), we use pdftotext. Output is clean and complete.

For scanned PDFs (FBI Vault case files, NARA historical scans), we use OCR — pages are rendered to images, then transcribed via Tesseract OCR. OCR quality varies; on heavily-redacted typewriter scans, text recovery is imperfect. Where this affects a summary, we say so explicitly in the "What to know" section.

3. The QA pipeline (zero error tolerance)

This is the heart of the project. Every public claim passes through a multi-agent verification chain.

Agent A — Extractor

Reads the source document and produces structured facts: a headline, a summary, key facts with source quotes, named people/places/dates/objects, and verifiable claims. Optimised for completeness — get everything.

Agent B — Verifier

Reads the source independently, with no knowledge of what Agent A produced beyond the claims themselves. For each claim Agent A made, Agent B marks it as supported, contradicted, not-in-source, or partial. Optimised for skepticism. Different prompt, fresh context.

Agent C — Adjudicator

If Agent A and Agent B disagree on a claim, Agent C reads the source again and adjudicates. Most disagreements are resolved by removing the unsupported claim.

Step D — Citation linker (deterministic)

For every surviving claim, we deterministically search the source text for the supporting quote. Quotes that match exactly get a "green" tier. Quotes where we can match a substantial substring get "amber" (partial citation). Claims with no recoverable quote get "red" — those are hidden from the public surface and queued for human review.

Agent E — Plain-English rewriter

Takes only the verified, citation-backed facts and writes the headline, summary, and narrative for the public surface. Has a hard rule: every sentence must trace back to one or more verified facts. Cannot introduce new claims.

4. Connection graph

The Network view links documents that share high-signal entities — places, projects, case numbers, sensor platforms, named people, object morphologies, and incident years. Edge weight uses inverse-document-frequency: rare entities (a specific person, a project codename) weigh more than common ones (USCENTCOM, AARO).

The result: 178 documents form 683 connection edges. Natural clusters emerge — the May 2022 CENTCOM cluster, the 1947–1949 flying-disc cluster, the Apollo crew debrief cluster, etc.

5. Confidence tiers

  • verified — Agents A and B agree, citation found in source. Highest confidence.
  • partial — Agents A and B agree but no clean source quote could be matched. Shown with hedging language.
  • queued — document is in the corpus but the QA pipeline hasn't run on it yet, or fabrication score was high enough to require human review.

6. Honest about what we cannot promise

Multi-agent verification catches an estimated 95% of LLM extraction errors. The remaining 5% — where all agents make the same mistake — has to be caught by reader-reported corrections. The "report an error" button on every document creates a GitHub issue. Every report is reviewed; verified errors trigger a correction with a public, append-only log.

OCR is not a perfect technology. Some scanned pages will have garbled output. We surface this in caveats rather than papering over it.

We do not interpret the documents. We report what they say. Many UAP cases involve unresolved sensor anomalies, ambiguous observations, and partially-redacted data. Where the documents themselves don't reach a conclusion, neither do we.

7. Update cadence

A daily scheduled task checks war.gov/UFO/ for new content. When a new tranche drops, the pipeline runs on the new documents within 24 hours. Re-redactions of previously-released documents (where a document gets re-released with different redactions) are detected by SHA-256 mismatch on the same filename, and surfaced as a separate "redaction changes" log.
