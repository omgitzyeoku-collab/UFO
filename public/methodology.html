How this works

The short version. We mirror every UAP document the US government publishes, byte-for-byte. A computer reads each one and writes a plain-English summary. A second, independent computer pass then tries to disprove every sentence of that summary against the original document. Anything it can't verify is hidden, not published.

Every summary is labelled with how confident we are, and every document links to the government's own original so you can check us.

The labels on every document

This is the most important thing on the site. Each summary carries one of these:

verifiedBoth passes agreed, and we found the supporting sentence in the original document. 881 documents.
partialBoth passes agreed, but we couldn't pin the claim to one clean quote. Written with hedged language. 12 documents.
hiddenWe could not substantiate it against the source, so we don't show a summary at all — only the original file. 117 documents.
queuedIn the archive, not yet processed. 23 documents.

The "hidden" pile is deliberate and we think it's the most honest number on the site. Most of it is heavily-redacted or badly-scanned material where a confident-sounding summary would be a guess. We'd rather show you nothing than invent something.

How to check our work

You should not take our word for any of this. Three ways to verify:

  1. Read the original. Every document page links to the government's own copy — war.gov, the National Archives, or the FBI Vault. Compare it to what we wrote.
  2. Read the raw text. Every document page has a "Document text" panel showing the exact machine-read text our summary was built from, warts and all.
  3. Check the bytes. Every file we mirror is fingerprinted (SHA-256). Download it from our archive, run sha256sum, and compare against our manifest — it will match the government's file exactly. We never alter a source file.

Found something wrong? Every document has a "report an error" link. Verified corrections are published in a public, append-only corrections log — we don't silently edit.

How a document becomes a summary

In plain terms, four things happen:

  1. We copy it. A crawler downloads the file from the government site and fingerprints it. The original is never modified.
  2. We read it. Modern PDFs give clean text directly. Old scans and photographed pages go through OCR (optical character recognition). Videos and audio are transcribed automatically.
  3. We summarise it — then attack the summary. One pass writes the summary. A second, independent pass re-reads the original with no knowledge of the first pass's reasoning and marks every claim as supported, contradicted, or absent. Where they disagree, a third pass re-reads the source and settles it — usually by deleting the claim. Finally we search the source text for a quote backing each surviving claim; no quote, no green label.
  4. We connect it. Documents sharing distinctive things — a person, a place, a project name, a sensor — get linked. Rare shared details count for more than common ones, so "USCENTCOM" links weakly and a named individual links strongly.
Technical detail (for people who want it)

Acquisition uses Playwright with a stealth profile (war.gov sits behind Akamai bot management). Files are stored content-addressably by SHA-256. Text extraction is pdftotext for born-digital PDFs and Tesseract OCR (via page rasterisation) for scans; audio/video use Whisper.

The verification chain is five stages: an extractor, an independent verifier in a fresh context with a different prompt, an adjudicator for disagreements, a deterministic citation-linker that string-matches quotes against the source, and a rewriter constrained to only the surviving verified facts. Runtime inference runs through the Claude CLI.

The connection graph weights shared entities by inverse document frequency. Full-text search is a prebuilt inverted index (152,017 words) loaded on demand. All of it is open source in the project repo — the pipeline is auditable end to end.

What we don't promise

Being straight about the limits:

  • Independent checking reduces errors; it doesn't eliminate them. Where every pass makes the same mistake, it survives. That's what the "report an error" link and the corrections log are for. We don't publish an accuracy percentage because we have no honest way to measure one.
  • OCR on 1940s typewriter scans is imperfect. Some pages come out partly garbled. We say so in the caveats rather than papering over it — and you can read the raw text yourself.
  • We don't interpret. We report what the documents say. Many cases are unresolved sensor anomalies, ambiguous sightings, and redacted data. Where the government's own investigators reached no conclusion, neither do we. A document saying "unresolved" is not a document saying "aliens".
  • Redactions are the government's, not ours. We show what was released. What's blacked out is blacked out at source.

How often it updates

An automated check watches war.gov every four hours and mirrors anything new. A weekly job then does the heavy work — transcribing, summarising, verifying — and publishes it. Release 4 (July 2026) was detected and largely processed without anyone touching it.
